One project, not two

The reading engine was a separate app with its own package.json, its own
node_modules, its own data folder and its own copy of the shared types. It is
now part of this repository, under engine/, and the desktop app starts it.

- The engine's sources moved here unchanged in behaviour, with two structural
  changes: it no longer serves an interface, because the app already renders
  everything and the two should only ever meet over the API and the exported
  schedule; and the types both halves agree on live in shared/, so a drift in the
  file format is a compile error rather than a column that silently renders
  empty.
- Its dependencies and esbuild are this project's now, so one npm install covers
  the app, the engine and the tests.
- Its data moved to the app's own data folder, under engine/. The database and
  the Telegram session came across intact, so the 1,271 messages already read
  are still there.
- The engine's name follows the app: what it prints, what it logs as, and what
  the model is told all say TheToDo. Only the database filename keeps its old
  name, because renaming it would orphan the history.
- The engine is quiet by default. The MTProto client wrote a version banner to
  stdout on every connect, which in a background process is noise that looks
  like a problem. THETODO_DEBUG=1 brings it back.
- Its bundle is found through a Rust command rather than a path built in the
  webview, so development and a packaged build resolve it the same way.

npm run build now builds the interface and the engine, and check:sync compares
them from the same tree instead of reaching across to another folder.

The old ClassRadar project is left untouched as you asked; nothing depends on it
any more.
